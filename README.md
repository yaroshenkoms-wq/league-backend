# league_backend

Сервер игры-прогнозов: матчи из CSV, прогнозы и очки в Firestore.

## Переменные окружения

См. `.env.example`. На хостинге обязательны `SERVICE_ACCOUNT` (JSON ключа Firebase одной строкой) и `ADMIN_KEY`.

## Календарь и результаты

Матчи лежат в CSV: чемпионаты — `matches.csv` (EPL), `LaLiga.csv`, `Bundesliga.csv`, `SerieA.csv`, `Ligue1.csv`;
еврокубки — `ChampionsLeague.csv`, `EuropaLeague.csv`, `ConferenceLeague.csv`;
дополнительные — `Championship.csv`, `Eredivisie.csv`, `PrimeiraLiga.csv`, `SuperLig.csv`, `ScottishPremiership.csv`, `NationsLeague.csv`
(у них `secondary: true` в `syncSchedule.js`: их клубы не влияют на названия клубов еврокубков).
Пустой CSV (только заголовок) при первой синхронизации заполняется названиями из фида как есть.
Актуальный календарь и счета подтягивает `syncSchedule.js` (fixturedownload.com + сверка счёта с football-data.co.uk):

- Сервер запускает его сам при старте и каждые 30 минут (`SYNC_ENABLED=false` отключает).
- Вручную: `node syncSchedule.js` — отчёт, `node syncSchedule.js --write` — записать CSV (копии в `csv_backup/`).
- Внепланово на сервере: `GET /api/sync` с заголовком `x-admin-key`.
- Результат можно вписать в CSV руками (`isCompleted=true` и `actualHomeScore`/`actualAwayScore`): синхронизация его не сотрёт.
- CSV перечитываются при изменении файла, перезапуск не нужен.
- Если синхронизация не смогла сопоставить команду, она пишет об этом в лог: добавьте псевдоним в `TEAM_ALIASES` (`matchUtils.js`).

Если лига ещё не назначила время матча, в CSV в дате стоит `TBD` (например, `Fri 09 Oct 2026 TBD`). Приложение показывает «Time TBA», а прогнозы на такой матч закрываются в 12:00 по местному времени лиги; когда время назначат, синхронизация подставит настоящее. Время матчей сервер отдаёт в UTC (`kickoff`), приложение показывает его по часовому поясу устройства.

ID матча чемпионата — `хозяева_гости` (например, `Arsenal_Coventry City`): он не меняется при переносе матча.
У еврокубков к нему добавляются турнир и тур (`Arsenal_PSG_UCL3`, `..._UEL3`, `..._UECL3`), потому что клубы одной страны могут встретиться в плей-офф.
Сервер отдаёт готовый ID в поле `matchId`, приложение сам его не собирает.

У Nations League (код `NL`) и Scottish Premiership (код `SPFL`) в ID тоже есть код и тур (`Spain_France_NL3`, `Celtic_Rangers_SPFL12`): в Шотландии за 33 тура пара встречается трижды.

### Еврокубки

- Источник один (fixturedownload.com): второго бесплатного источника для сверки счёта нет, поэтому результаты еврокубков **не сверяются**. Защита: результат записывается только через 135 минут после начала (запас на дополнительное время), счёт с более чем 15 голами отбрасывается.
- Результат в фиде — итоговый счёт матча; для плей-офф с дополнительным временем и пенальти проверяйте его вручную.
- Плей-офф появится в фиде после жеребьёвки: число матчей в файле может расти, но не уменьшаться.
- Названия клубов приводятся к названиям из национальных чемпионатов, если совпадают точно ("Man City" → "Manchester City"); остальные остаются как в фиде. Время матчей записано по центральноевропейскому времени.

## Резервные копии

Двойной щелчок по `Сделать бэкап базы.command` (в корне проекта) сохраняет в `backups/`:

- `backup-<дата>.json.gz` — пользователи и прогнозы из Firestore. После записи файл перечитывается и сверяется с базой; хранятся последние 30 (`BACKUP_KEEP`).
- `auth-<дата>.json` — аккаунты Firebase Auth (нужен `firebase login`). Файл содержит хеши паролей, поэтому права `600`, папка `backups/` не попадает в git. Не отправляйте его никому.

Команды: `node backup.js list` — список копий; `node backup.js restore <файл>` — показать содержимое; `node backup.js restore <файл> --yes` — восстановить (документы с теми же ID перезаписываются, лишние не удаляются).
Аккаунты из `auth-*.json` возвращаются командой `firebase auth:import`.

Копии лежат на вашем компьютере: сохраняйте ещё одну вне него (iCloud, флешка). Копия делает столько чтений, сколько документов в базе.

## Начисление очков

Каждые 5 минут (и сразу после появления новых результатов) сервер считает необработанные прогнозы пакетами по 200 штук.
Параллельные запуски исключены, повторно очки не начисляются. Прогнозы читаются только по новым завершённым матчам, каждый матч проверяется один раз.

Очки хранятся в профиле пользователя: общие (`points`) и по лигам (`pointsByLeague`). Рейтинг лиги читает только профили, а не все прогнозы.

**Пересчёт очков** (`GET /api/recalculate`, заголовок `x-admin-key`) пересчитывает всё с нуля из прогнозов и текущих результатов:
- без параметров — только показывает, что изменится, ничего не пишет;
- `?apply=1` — записывает исправления. Нужен после исправления результата матча и один раз после обновления с прежней версии (заполняет `pointsByLeague`). Пока пересчёта не было, рейтинг лиги считается по прогнозам, как раньше, просто читает больше данных.

Проще всего запускать ярлыком `Пересчитать очки.command` (в корне проекта): он сам делает копию базы, показывает, что изменится, и записывает только после вашего `yes`. Запускать после выкладки новой версии сервера, а не до неё.

## Новые возможности API

- **Живой счёт** (`liveScores.js`): ESPN scoreboard, опрос раз в 2 минуты, только лиги с матчем в окне `[сейчас-3ч, сейчас+5мин]`. Поле `live: {home, away, minute, status: in|ht|ft}` в `GET /api/matches/:slug`. На очки не влияет. `LIVE_ENABLED=false` отключает. Ошибки ESPN — максимум одно предупреждение в час на лигу.
- **Джокер**: `POST /api/predictions/joker {matchId, on}` — очки за матч ×2; один на лигу и тур. Ошибки: `no_prediction` (404), `match_started`, `joker_used` (400). Прогнозы хранят `round` и `joker`.
- **Статистика матча**: `GET /api/matches/insights/:matchId` (без входа, кеш 60 с): до начала только `total`, после — `outcomes` (%) и `topScores`.
- **Лиги друзей**: `scoring {exact, diff, outcome}` (по умолчанию 3/2/1) в `POST /api/groups` и `PUT /api/groups/:id/scoring` (владелец); `GET /api/groups/:id/match/:matchId` — прогнозы друзей (после начала матча).
- **Чат лиги**: `GET|POST /api/groups/:id/messages`, `DELETE .../messages/:msgId`, `POST .../messages/:msgId/report` (в коллекцию `reports`). Брань маскируется (`chatFilter.js`), лимит 20 сообщений в минуту.

## Служебные эндпоинты

| Эндпоинт | Доступ | Назначение |
|---|---|---|
| `GET /api/health` | открыт | проверка доступности; на нём удобно настроить внешний пинг (UptimeRobot), чтобы бесплатный хостинг не засыпал |
| `GET /api/status` | открыт; с `x-admin-key` — с числом пользователей и прогнозов | состояние сервера и синхронизации |
| `POST /api/predictions/batch` | токен Firebase, почта подтверждена | до 20 прогнозов за раз (кнопка «Save all»); ответ содержит результат по каждому, ошибка одного не мешает остальным |
| `DELETE /api/account` | токен Firebase, пароль подтверждён не более 5 минут назад | удаляет прогнозы, профиль и аккаунт пользователя (порциями по 400; запрос можно безопасно повторить) |
| `GET /api/check` | `x-admin-key` | внеплановое начисление очков |
| `GET /api/recalculate` | `x-admin-key` | пересчёт очков; `?apply=1` — записать |
| `GET /api/sync` | `x-admin-key` | внеплановая синхронизация |
